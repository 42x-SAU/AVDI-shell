# AVDI Shell — веб-интерфейс

## Краткое описание

**AVDI Shell** — одностраничное (SPA) веб-приложение на React для работы с внутренней диагностикой инфраструктуры. На текущем этапе реализованы архитектурный каркас, главная страница в виде продуктового лендинга-заготовки, адаптивная вёрстка, светлая и тёмная темы, индикатор загрузки (красная полоса сверху) и базовая подготовка к подключению backend.

Backend, база данных и агенты в этом репозитории **не** реализуются — только frontend.

## Стек технологий

- **React** (JavaScript, без TypeScript)
- **Vite** — сборка и dev-сервер
- **react-router-dom** — маршрутизация SPA
- **nprogress** — верхняя полоска загрузки
- **axios** — заготовка HTTP-клиента для будущего API
- **ESLint** — базовая проверка кода

Вёрстка: **HTML5**, **CSS3** (переменные темы, media queries, flex/grid), без тяжёлых UI-фреймворков.

## Требования к окружению

- **Node.js** LTS (рекомендуется 20.x или новее)
- **npm** (поставляется с Node.js)

## Установка зависимостей

В корне проекта выполните:

```bash
npm install
```

## Запуск в режиме разработки

```bash
npm run dev
```

После запуска откройте в браузере адрес, который выведет Vite (обычно `http://localhost:5173`).

## Production-сборка

```bash
npm run build
```

Статические файлы появятся в каталоге `dist/`. Просмотр собранной версии локально:

```bash
npm run preview
```

## Проверка линтером

```bash
npm run lint
```

| Путь | Назначение |

| `src/layouts/` | Обёртки страниц (общий layout с шапкой и подвалом) |

## Светлая и тёмная тема

- Тема задаётся через атрибут `data-theme` на корневом элементе (`light` / `dark`) и CSS-переменные в `src/styles/theme.css`.
- Переключатель находится в шапке (на широких экранах) и в выезжающем меню (на узких).
- Выбор пользователя сохраняется в `localStorage` под ключом `avdi-shell-theme`. Значения: явные `light` / `dark` или режим «системная тема» (`system`), если пользователь ещё не задавал предпочтение.
- При первом визите без сохранённой темы учитывается `prefers-color-scheme` (также встроен небольшой скрипт в `index.html`, чтобы уменьшить мигание цветов до загрузки React).
- Переключение темы без перезагрузки страницы; цвета и фоны меняются плавно.

## Будущее подключение backend

- Базовый HTTP-клиент: `src/services/apiClient.js` (axios), `baseURL` берётся из переменной окружения `VITE_API_BASE_URL`.
- Реальные endpoint’ы и контракты API **не** заданы — добавляются по мере готовности backend.
- Рекомендуемый порядок интеграции: описать функции доступа к API в `src/services/`, вызывать их из страниц или хуков, при необходимости добавить слой авторизации в перехватчики axios.

## Панель мониторинга (`/app`) и API

Данные dashboard запрашиваются через `axios` (`src/services/apiClient.js`), базовый адрес — **`VITE_API_BASE_URL`**.

Если в шапке панели видно **«Задайте VITE_API_BASE_URL»** или данные не загружаются:

1. Для **`npm run dev`**: создайте **`.env.development.local`** (можно скопировать из `.env.example`) с `VITE_API_BASE_URL=/api` и при необходимости `VITE_DEV_PROXY_TARGET` — см. `vite.config.js` (прокси снимает блокировку CORS в браузере).
2. Файл **`.env.local`** подхватывается Vite **и при сборке** — не кладите туда `/api` без прокси на проде; для только-dev настроек используйте **`.env.development.local`**.
3. Перезапустите dev-сервер после изменения `.env*`.
4. Для **`npm run build`** / деплоя задайте реальный API в **`.env.production`** / `.env.production.local` (полный `http://...`) или настройте reverse proxy на своём веб-сервере под префикс `/api`.

Проверка: в консоли браузера (вкладка «Сеть») запросы к `/api/agents` (или к полному URL) должны отвечать **200**, не **CORS error** и не **404** с адреса dev-сервера для статики.

## Переменные окружения

Пример файла — **`.env.example`**.

| Переменная | Описание |
|------------|----------|
| `VITE_API_BASE_URL` | Базовый URL API без завершающего `/`. Для `npm run dev` часто задают `/api` и прокси в `vite.config.js`. Пустое значение — запросы уйдут на origin dev-сервера (данные не подтянутся). |
| `VITE_DEV_PROXY_TARGET` | (Только dev) Куда проксирует префикс `/api`. По умолчанию задан в конфиге Vite. |

Скопируйте `.env.example` в **`.env.local`** (рекомендуется) или `.env` и задайте значения. Vite подставляет только переменные с префиксом `VITE_`.

## Что реализовано сейчас и что остаётся заготовкой

**Реализовано:**

- Сборка Vite, React SPA, react-router-dom с одной главной страницей и fallback-редиректом на `/`.
- Общий layout: шапка с логотипом и бургер-меню, подвал с колонками-заглушками, главная страница с блоками hero / преимущества / сценарии / масштабируемость.
- Адаптивная вёрстка, доступность: семантика, `aria-*` у бургера и меню, ссылка «Перейти к содержимому».
- Светлая/тёмная тема, сохранение настроек, плавные переходы.
- Красная полоска загрузки (nprogress) при первой загрузке, обновлении страницы и смене маршрута.
- Favicon и логотип подключены по описанным путям.
- README на русском языке.

**Заготовки под будущее:**

- Отдельные разделы меню («Обзор», «Отчёты» и др.) отображаются как неактивные пункты.
- Кнопки действий на главной без бизнес-логики.
- `apiClient` без конкретных маршрутов и сценариев авторизации.
- Тексты в подвале и части ссылок — осмысленные заглушки для замены на реальные данные проекта.
